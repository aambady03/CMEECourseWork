Detailed Evaluation: TAutoCorr.R

A. Specification Alignment

Observed in submitted TAutoCorr.R (from LOG contents): - Successive-year correlation via cor(): ✓ (obs_cor <- cor(temps[-length(temps)], temps[-1])) - Permutation null distribution: ✓ (loop of n_perm <- 10000, sample(temps), recompute cor()) - Approx p-value: ✓ (p_value <- mean(perm_cor >= obs_cor)) - Did not use cor.test(): ✓ - Non-interactive run: ✓ (runs under Rscript --vanilla) - Relative path handling: Partially (uses here::here("groupwork2","data",...) which is robust if project root is as expected)

B. Conceptual Understanding of Autocorrelation

  • Explicitly constructs successive-year pairs by offset indexing (temps[-length] vs temps[-1])
  • Breaks temporal structure in the null by permuting the series (sample(temps))
  • Reports observed correlation and permutation p-value, with an interpretation statement
  • Clear conceptual grasp of lag-1 (successive year) association and why permutation provides a null distribution when temporal ordering is meaningful.
  • Uses a one-sided test aligned with “positively correlated” language in the script output.

C. Algorithmic Implementation Depth (vs example solution)

Compared to TAutoCorr_sol.R: - Similarity: Both compute lag-1 correlation, generate a permutation null, compute a permutation p-value, and (optionally) visualise the null distribution. - Difference (structure): Example solution defines a function (autocor_test) and uses more explicit modular structure; the submitted script is single-pass (no function), but still clear. - Indexing/lag handling: Correct and clean in the submitted script. - Efficiency: Uses preallocated perm_cor <- numeric(n_perm) and a loop: acceptable at bootcamp level.

D. Statistical & Computational Rigor

  • Uses cor() consistently for observed and permuted statistics.
  • Uses a clear null distribution and an empirical p-value estimate.
  • One-sided p-value computed as mean(perm_cor >= obs_cor); this is coherent with “positively correlated” framing.

Potential improvement: - Consider whether a two-sided p-value is more appropriate depending on the question wording; if keeping one-sided, state that explicitly in the write-up.

E. Error Handling & Robustness (Criterion 8 alignment)

  • Minimal explicit input validation (assumes dat$Temp exists and has length > 1).
  • Would fail on very short series or missing Temp column.

Suggested robustness additions: - Check file exists before load() - Assert length(temps) >= 3 (or at least 2) before computing correlations - Handle missing values (NA) explicitly if present

Similarities

  • Permutation null distribution
  • Empirical p-value estimation
  • Optional histogram-style visualisation

Key omissions

  • No function abstraction (acceptable, but less reusable)
  • No explicit handling of NA or short series edge cases
